Especificaciones de Animación

Guía técnica detallada sobre la lógica de capas, ciclos "Ping-Pong" y directrices de implementación para desarrollo móvil.

1. La Lógica "Ping-Pong"

El término "Ping-Pong" se refiere a una técnica de animación donde una secuencia de fotogramas se reproduce hacia adelante y, al llegar al final, se reproduce en reversa para volver al punto de inicio. Esto evita saltos bruscos ("hard resets") y crea bucles fluidos y orgánicos, ideales para respiraciones, parpadeos o movimientos pendulares (como mover la cola).

Ejemplo conceptual: En lugar de reproducir [1, 2, 3, 4] -> [1, 2, 3, 4] (lo que causaría un salto del 4 al 1), reproducimos [1, 2, 3, 4, 3, 2] -> [1, 2, 3, 4, 3, 2].

2. Deconstrucción de Capas (Estado: Despierto)

El estado "Awake" es un compuesto de 3 capas independientes. Es crucial entender que estas capas no están sincronizadas entre sí; cada una tiene su propia duración y reglas para sentirse viva.

Capa 1: Fondo (Cuerpo)

Iniciando...

Cuerpo (Raise & Wag)

La animación del cuerpo es la más compleja del estado base. No es un simple loop continuo. Está dividida en dos fases para simular que el coyote se despierta/levanta y luego se queda en un estado de alerta expectante.

Fase 1: El Levantamiento (Intro Secuencial)

Comienza desde el estado base estático. Al activarse, reproduce la secuencia del 1 al 7 una sola vez. Esto simula cómo levanta la cabeza, endereza el cuerpo y alza la cola.

base -> raise_1 -> raise_2 -> raise_3 -> raise_4 -> raise_5 -> raise_6 -> raise_7

Fase 2: Bucle Restringido (Ping-Pong)

Una vez que llega a raise_7, nunca vuelve al frame 1. En su lugar, entra en un loop de Ping-Pong restringido entre los frames 4 y 7. Esto simula la respiración y el ligero movimiento de la cola sin que el coyote vuelva a bajar completamente.

[Loop Infinito]: raise_7 -> raise_6 -> raise_5 -> raise_4 -> raise_5 -> raise_6 -> raise_7

Ruta: assets/coyote/Medium/awake/body/

Capa 2: Medio (Rostro)

Esperando...

Rostro (Parpadeo Aleatorio)

El rostro descansa sobre el cuerpo. Su función principal es darle vida mediante parpadeos impredecibles. Un parpadeo en un intervalo fijo se ve robótico.

  • Estado Base: Permanece estático en base.png mostrando los ojos abiertos.
  • Intervalo: Un temporizador aleatorio (ej. entre 2 y 6 segundos) dispara la animación.
  • Acción (Ping-Pong): Reproduce rápidamente los frames blink_1 hasta blink_8 (ojos cerrados) y regresa del 8 al 1.
base.png (Espera Aleatoria) ➔ [1,2,3,4,5,6,7,8,7,6,5,4,3,2] ➔ base.png

Ruta: assets/coyote/Medium/awake/face/

Capa 3: Frente (Efectos)

Efectos (Love Layer)

Esta es la capa superior. A diferencia de las demás, no utiliza lógica Ping-Pong. Es una secuencia lineal estricta diseñada para reproducirse constantemente sin interrupciones.

Loop Continuo Secuencial

El ciclo va desde el frame 1.png hasta el 21.png de manera secuencial. Al terminar el frame 21, salta inmediatamente al frame 1, ya que la animación está diseñada para conectar el último frame con el primero sin saltos perceptibles.

Ruta Corregida: assets/coyote/Medium/love/ (NO en awake/)

3. Estado Dormido (Sleep)

Una sola capa

Cuando la aplicación entra en estado de inactividad, se cambia completamente la vista. El estado Sleep es mucho más sencillo estructuralmente, ya que colapsa todas las animaciones en una sola secuencia base.

  • Ping-Pong Simple Simula la inhalación y exhalación. Sube de 1.png a 8.png (inhalar) y regresa bajando de 7.png a 2.png (exhalar).
  • La Secuencia [1, 2, 3, 4, 5, 6, 7, 8, 7, 6, 5, 4, 3, 2]

Ruta: assets/coyote/Medium/sleep/

4. Guía de Implementación Mobile (iOS & Android)

Directrices Críticas de Arquitectura UI

A. Apilamiento de Capas (Z-Index)

Para el estado Awake, debes superponer 3 vistas de imagen exactas. Ambas plataformas requieren contenedores específicos para lograr esto de forma responsiva y manteniendo la misma relación de aspecto.

iOS (SwiftUI) 
ZStack {
    Image("body_frame") // Fondo
    Image("face_frame") // Medio
    Image("love_frame") // Frente
}
Android (XML/Compose) 
// Compose
Box {
    Image(...) // Body
    Image(...) // Face
    Image(...) // Love
}
// XML: Usa FrameLayout o ConstraintLayout

B. Temporizadores Independientes y Hilos de UI

REGLA DE ORO: Nunca vincules la animación de las tres capas a un solo Timer o bucle. Dado que el Cuerpo tiene ~4 frames en loop, el Rostro parpadea asíncronamente y Love tiene 21 frames, un bucle maestro arruinará el "timing".

Estrategia iOS
  • Evita bloquear el Main Thread. Usa Timer.publish(every:...).autoconnect() independientes en SwiftUI.
  • Para UIKit, considera crear 3 instancias de UIImageView y asigna arrays independientes a su propiedad animationImages estableciendo sus respectivos animationDuration. El Rostro requeriría un Timer manual para disparar el parpadeo.
Estrategia Android
  • Utiliza Kotlin Coroutines (viewModelScope.launch o lifecycleScope) para crear bucles while(isActive) { delay(ms) } para gestionar el índice de los frames.
  • Actualiza el estado (StateFlow) que la UI de Compose observa.
  • Alternativamente, crear animaciones XML en res/drawable tipo <animation-list> para Body y Love, programando el Face vía código.
